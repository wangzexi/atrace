# atrace：个人数字足迹档案

atrace 把散落在不同平台的数字足迹汇成一份由自己掌握的档案。发过的帖子、参与过的讨论、点赞、收藏和转发过的内容，都可以跨平台回看，也可以交给 AI 查询。你还可以选出一部分公开，让它成为自己的个人主页。

## 档案怎么组织

- **谁做了什么。** 用同一套方式记录账号、内容和活动。你收藏了一篇文章和你写了一篇文章，是两种不同的活动；查询时可以分别看，也可以放在同一条时间线上。
- **人可以跨平台。** 你可以把同一个人的多个平台账号归在一起，包括自己的账号。这样既能看自己的时间线，也能查看档案中观察到的某个人的内容和活动。
- **采到了什么，就记录什么。** 平台能提供的信息不一样。档案可以保留来源和原始材料，以便回查；不知道的事不猜，采到的记录也不代表一个人在平台上的全部活动。
- **一份档案，多种用法。** 时间线、搜索、个人主页和 AI 查询都使用同一份档案。页面长什么样、哪条内容公开，由展示和使用场景决定。

## 谁能看到

采集到的内容默认归档案主人自己。主人可以看和搜索完整档案，也可以选择公开具体内容；访客只看到公开的那部分。它可以只在自己电脑上使用，也可以把公开页面作为个人主页。

## 产品边界

atrace 解决的是个人信息散落在各平台、难以长期保存和查找的问题。它不做另一个社交平台，不提供新的点赞、回帖、推荐或社区；AI 是档案的使用者。

## 档案终端

打开站点的 `/terminal` 或运行 `atrace sh`。主人从 `/atrace` 按人物和月份进入条目目录。访客按月份浏览默认人物的公开记录。用 `grep` 找正文和文本附件，用 `cat` 读 `entry.md` 或 `entry.json`，用 `atrace download` 保存附件。站点的 `/terminal.md` 是目录说明，`atrace sh --help` 列出可用命令。

Blog 成稿采集后，可以用 `atrace blog-drafts <本地 Blog 目录>` 同步各篇文章 `refs/drafts/` 下的 Markdown 和纯文本。同步的草稿归档在对应文章的附件目录，仅主人可见。
