# 采集器（给 AI 读）

Atrace.app 在本机按每个采集器的 `cron` 定时运行它，采集器把读到的内容直接提交给服务端。采集器只做三件事：从平台读数据、转换成标准文档、提交。

## 目录结构

采集器目录是 `~/.atrace/collectors/`（或环境变量 `ATRACE_COLLECTORS` 指定的目录）。**只有放在这里的才会运行。** 装好时它是空的，用户要采什么，就照他说的建。

每个采集器是这个目录下的一个文件夹，文件夹名就是平台名：

```
weibo/
  index.mjs      入口，`bun index.mjs` 运行，工作目录是这个文件夹
  config.json      用户设置，必须有
  emoji.mjs        可选的辅助脚本，只能手动运行，不进入定时
```

`config.json` 是这个采集器唯一的设置文件：

- `cron`：五段 cron，按设备时区。必填；不合法或缺失，这个采集器不会运行。
- `paused`：可选，`true` 时不定时运行（手动运行仍然可以）。
- 其它字段是平台参数，例如 `profileId`（用哪个浏览器 profile）、`accountId`（采别人时的目标账号），由 `index.mjs` 自己读取。

`index.mjs` 顶部的 `VERSION` 是复制时所用示例的版本号，只用于比对；示例更新后，已复制的采集器不会自动更新。

采集器之间互不依赖，不共享代码，也不引用文件夹之外的任何东西。每个采集器自带它需要的协议代码。示例用 ego 浏览器驱动页面，那是示例的选择；别的采集器可以用别的办法，只要能拿到用户的登录态和数据。

## 两种采集器：采自己，采别人

登录态是所有采集器的前提：都用浏览器里已登录的会话去读平台。区别只在采谁的数据，由文件夹名区分：

| 文件夹 | 采谁 | 采什么 |
|---|---|---|
| 平台名本身：`weibo`、`xiaohongshu`、`x`、`zhihu`、`bilibili`、`douyin`、`github` | 当前登录的账号本人 | 发布、评论，加上只有本人看得到的点赞、收藏（`github` 只采 star 的仓库） |
| 平台名加 `-user`：`weibo-user`、`xiaohongshu-user` | `config.json` 里 `accountId` 指定的另一个账号 | 他公开的发布和评论，不采点赞、收藏 |

- **采自己的那份，文件夹名必须等于平台名。** 用户在页面里打开一条帖子时，服务端按平台名（例如 `weibo`）通知设备去读，只有叫这个名字的采集器收得到。
- **采别人的那份，文件夹名随便起**（复制 `weibo-user` 后改成 `weibo-alice` 之类）。每个采集器彼此独立，所以要把 `index.mjs` 里的 `TASK_SPACE` 和 `OBSERVED_BY` 也改成自己的名字，不要和别的采集器重名。它收不到"打开一条帖子"的通知。
- `-user` 的 `config.json` 多一个必填的 `accountId`（目标账号在平台上的 ID），登录的账号不必是它。读到的内容作者不是它就报错，任务空间属于别的 profile 也报错。
- 现在只有微博和小红书有 `-user`。别的平台需要时，照这两个改。

## 运行

- 命令：`bun index.mjs`，工作目录是采集器文件夹。
- 环境变量：`ATRACE_SERVER`（服务端地址）、`ATRACE_COLLECT_TOKEN`（采集令牌）、`ATRACE_TARGET`（可选，只读一条，格式 `平台:类型:ID`）、`ATRACE_FULL=1`（可选，读全部历史）。
- 单次运行最长 60 分钟。采集器一次只跑一个：手动请求排在队列里，定时任务在队列空时才运行；不抢占正在跑的任务。
- 输出：`ATRACE_ACCOUNT <账号ID> <名字>` 报告当前登录的账号；最后一行 JSON 是摘要（计数等）。失败时抛异常，退出码非零。
- 错误信息含 `not logged in` 会显示「未登录」并停止重试；含风控关键词（如 `captcha`、`风控`、`403`、`429`）会标记为 `blocked` 并停止定时运行，直到修改该采集器的文件或重启 App。
- 日志写入 `ATRACE_HOME/logs/<平台>.log`。

## 提交给服务端

采集器只调用这几个接口（都带 `Authorization: Bearer <ATRACE_COLLECT_TOKEN>`）：

| 接口 | 做什么 |
|---|---|
| `POST /collect/ingest` | 提交一个文档，body 为 `{observed_at, observed_by, raw?, document}`。新增返回 201，已存在无变化返回 200 |
| `POST /collect/known` | 批量查询哪些动作已入库，每批最多 500 项，返回与输入顺序对应的 `known` 数组 |
| `GET /collect/media?url=` | 查询媒体是否已有本地副本 |
| `PUT /collect/media?url=` | 上传媒体字节，登记为 `url` 的副本 |

`url` 是写进文档的稳定地址，另一个 `source` 是本次看到的（可能带签名的）下载地址。

### 文档

- ID 是 `平台:类型:ID`。引用字段只写 ID 字符串，被引用的对象没采集过也可以。
- 每个有作者的内容（帖子、文章、视频、评论）有一条 `Create`，`actor` 是作者账号。作者本人的 `Person` 文档一并提交，页面才能显示名字。
- 点赞 `Like`、转发 `Announce`、收藏 `Add`（带 `target` 收藏夹）、取消 `Undo` / `Remove`。收藏夹可以只是一个稳定的 ID（如 GitHub 的 `github:star:<账号>`），不必另存 Collection 文档；页面按动作把 `Add` 显示为「收藏」。引用和回复是内容之间的关系（`quote`、`inReplyTo`），不是动作。
- 没有发生时间的动作（点赞、收藏）从最旧到最新提交，让顺序等于操作顺序。
- 只记录观察到的事实。平台没给的字段不要猜；两个账号是不是同一个人，由用户在页面里决定，采集器不合并。
- 平台自己的写法造成的问题在采集器里处理：重复的标题、正文末尾的引用链接、话题标记、随请求变化的签名或域名（只记稳定部分，否则每次运行都会产生新版本）。展示层的映射（如微博的表情图）留给前端。原始响应放在 `raw`。

## 增量读取

一次普通运行从最新往前读列表：每读一页，把这页每一项的动作交给 `POST /collect/known`，没入库的才继续处理。连续 `KNOWN_RUN`（5）条已入库就认为读到了上次的位置，停止。页数上限只是首次导入和追赶时的安全边界。`--full` 读全部。

## 读取一条（ATRACE_TARGET）

用户在页面里打开一条帖子时，服务端通知设备，设备用同一个脚本读这一条和它的首页评论，然后结束。`ATRACE_TARGET` 为空时是普通运行。每个脚本只认自己平台的目标格式，其它的拒绝。

## 写一个新的

1. 先定是采自己还是采别人（见上），复制最接近的示例文件夹，按上面的规则起名。`config.json` 里的 `cron` 按平台能容忍的频率定（不要小于一小时，除非平台没有风控），先设 `"paused": true`。
2. `index.mjs` 的文件头写清楚读什么、写什么、不采什么。顶部放常量（`ATRACE_API`、`PROFILE_ID` 等）。
3. 上半是纯转换函数：平台响应 → 标准文档，不碰网络和浏览器。分界处写一行 `// ==== side effects below`。下半是请求、翻页、下载、入库顺序。
4. 结尾输出一行 JSON 摘要。
5. 试跑：`atrace collect <平台>`，检查摘要和服务端数据。跑通后去掉 `paused`。

### 测试

- 离线：`bun test client/app/tests/collectors/` 用 `<平台>/testdata/` 里的合成响应检查转换结果，并检查契约（ID 前缀、引用是 ID 字符串、`Add` 带 `target`、附件是 https）。
- 幂等：`client/app/tests/collectors/check-idempotency.sh <平台>` 连跑两次，第二次有新增就失败。需要本机浏览器环境和运行中的服务端。

## 不要做

- 不要 import 其它采集器或任何共享模块。
- 不要把账号密码、cookie、令牌写进文件；登录态只在用户的浏览器里。
- 不要发布、点赞、关注、删除。采集器只读。
- 不要在用户的主目录里另建 `.atrace-*` 目录。持久文件只放在 `ATRACE_HOME` 里。
- 不要为了复用而加配置项。要新的可调参数，就在 `index.mjs` 顶部写常量，或在 `config.json` 里加字段，并在本文档说明。

服务端管理（人物、账号、隐藏、公开）不属于采集器，用 `atrace --help` 查看 CLI 的命令。

辅助脚本（如 `weibo/emoji.mjs`）用 `atrace collect <平台> --script=emoji` 手动运行。
